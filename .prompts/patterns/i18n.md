# Internationalization

## Python side

Define the bound translation functions once, in the plugin package's
`__init__.py`:
```python
from indico.util.i18n import make_bound_gettext

gettext = _ = make_bound_gettext('<pluginname>')
ngettext = make_bound_ngettext('<pluginname>')
```
Import `_`/`gettext`/`ngettext` from there everywhere else in the plugin
(`from indico_<pluginname> import _`). Never call the unbound core
`gettext` for plugin strings — it won't resolve translations from the
plugin's own catalog.

## Extraction workflow (pybabel)

This part of the old `indico-plugin-example` README is still structurally
accurate:
```bash
pybabel extract -o indico_<pluginname>/translations/messages.pot indico_<pluginname> -F babel.cfg
pybabel extract -o indico_<pluginname>/translations/messages-js.pot indico_<pluginname> \
    --no-default-keywords -k 'gettext' -k 'ngettext:1,2' -k '$T' -F babel-js.cfg
```
Adding a new language:
```bash
pybabel init -l de_DE -i indico_<pluginname>/translations/messages.pot -d indico_<pluginname>/translations/
```
Updating after string changes:
```bash
pybabel update -i indico_<pluginname>/translations/messages.pot -l de_DE -d indico_<pluginname>/translations
```

## What's different from the old example

Compiling `.po` → `.mo` is **no longer a manual packaging step**. Copy the
shared `hatch_build.py` hook pattern from a reference plugin
(`indico-plugins/hatch_build.py`, referenced via a relative path from each
plugin's `pyproject.toml`):
```toml
[tool.hatch.build.targets.sdist.hooks.custom]
path = '../hatch_build.py'
dependencies = ['babel==2.18.0']
```
This compiles translations automatically at build time. Don't add a
manual `pybabel compile` step to packaging docs/CI for a new plugin that
lives alongside other plugins sharing this hook — only do it standalone if
the plugin has no sibling `hatch_build.py` to point at.

## React/JSX strings

If the plugin has React components, string extraction additionally goes
through a `messages-react.po`/`.json` pipeline compiled via
`npx react-jsx-i18n compile`, also wired into the shared `hatch_build.py`.
See `.prompts/patterns/assets-frontend.md` for the client-code side.
